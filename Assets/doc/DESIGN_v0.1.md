## 1. 文档目的

本文档定义 asrGUI 的产品范围、交互流程、技术架构、数据格式、运行目录、打包方式和质量标准。开发阶段、里程碑、交付顺序和出口条件见配套的 [ROADMAP_v0.1.md](ROADMAP_v0.1.md)。

当前设计基线如下：

1. 当前为个人自用项目，使用 Personal Team；暂不考虑公开发布、分发和商店上架。
2. 打包偏好为自包含方案：不依赖用户本机安装 Python、FunASR、PyTorch、FFmpeg 或模型。
3. 第一阶段只导入本地音频，不做麦克风录音和系统音频捕获。
4. 主要语言为普通话；成员相对固定，通过历次会议音频人工确认后建立声纹，不提供专门录音建档流程。
5. 参数配置接受“枚举项下拉、数值项数字框/滑杆、高级参数 JSON”的方案。
6. LLM 使用 OpenAI-compatible 接口，当前优先考虑 DeepSeek。
7. 会议报告输出 Markdown，暂不固定模板。
8. 实验阶段将运行环境和转写数据集中放在项目内的 `AppFile` 下；正式版首次启动时提供数据目录选择。
9. 开发、调试、构建和打包均在项目内的 `Codex_work_space` 下进行。
10. 报告默认包含句子级、可点击且可复制的时间引用，不要求词级时间引用。
11. 声纹逐成员人工确认建档，不从旧会议批量建立声纹。
12. Windows 仅保留 x64 构建路径，暂不考虑 Windows ARM64。

本文档是实现、测试和验收的设计基线。任何会改变数据格式、打包边界、LLM 请求内容或用户数据位置的设计变更，应通过新增文档版本记录。

## 2. 产品概述

asrGUI 是一个面向会议音频的本地桌面工作台。用户导入会议录音后，应用使用本地 FunASR 完成语音识别、分句、标点和说话人区分，生成带时间戳的结构化 JSON。界面按时间和说话人展示转写文本，点击文本中的 token 可跳转到对应音频位置。随后用户可以调用在线 LLM 进行受控纠错，并在确认后的文本上生成 Markdown 会议报告。报告中的时间引用以句子为粒度，可在应用内点击定位，也可复制时间。

产品有三个基本原则：

1. **音频识别本地完成。** ASR 模型随应用打包，推理不依赖云服务。
2. **原始结果不可变。** 原始 ASR JSON、纠错稿和报告均保留版本，任何模型或人工修改都可追溯。
3. **应用环境自包含。** 最终应用携带私有 Python 运行时、依赖、音视频工具和 ASR 模型，不要求用户预装开发环境。

## 3. 范围

### 3.1 第一阶段范围

- 导入本地音频文件。
- 展示会议库、导入进度和处理状态。
- 使用本地 FunASR 完成离线转写。
- 输出字/词级时间戳和结构化 JSON。
- 根据时间戳与说话人展示会议对话。
- 点击文本跳转并播放对应音频。
- 自动说话人聚类，支持人工改名。
- 从历次会议中人工确认的说话片段建立声纹档案。
- 新会议自动匹配固定成员，无法可靠匹配时标记为未知说话人。
- 可配置 FunASR 常用和重要参数。
- 通过 OpenAI-compatible LLM 接口进行分段纠错。
- 保留原始文本、纠错文本和差异。
- 生成并保存 Markdown 会议报告，默认带句子级可点击、可复制时间引用。
- 打包为可离线运行的 macOS `.app`。
- 在源码、依赖和打包脚本层面保留 Windows x64 构建入口。

### 3.2 第一阶段不做

- 实时麦克风录音。
- macOS/Windows 系统音频捕获。
- 实时流式字幕。
- 多用户协作和云同步。
- 自动加入会议平台。
- 专门录制声纹的向导。
- 从旧会议批量建立声纹档案。
- 固定强制的会议报告章节。
- 自动更新机制。
- macOS 与 Windows 交叉编译。
- Windows ARM64 支持。
- 公开发布、Developer ID 签名、notarization、商店上架和分发所需元数据。

### 3.3 成功标准

第一阶段的成功不是“模型效果永远正确”，而是形成一条可靠、可恢复、可检查的本地会议处理链路：

- ASR 在断网环境下可完成转写。
- 每条转写句子和可点击字/词都有可解释的时间信息。
- 点击文本后播放器在可接受误差内跳转。
- 说话人可人工修正并沉淀为本地声纹。
- LLM 修改不会覆盖原始转写。
- 报告默认包含句子级可点击、可复制时间引用。
- 最终应用可在未安装 Python 和 FFmpeg 的 macOS 上运行。
- 所有应用自有的业务数据均可在用户选定或开发默认的数据根目录内找到。

## 4. 已确认的关键设计决策

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D-01 | macOS Apple Silicon 为当前目标 | macOS Apple Silicon 是主要开发和验收平台；Windows 仅保留 x64 构建路径，暂不支持 Windows ARM64 |
| D-02 | 桌面技术采用 Python + PySide6 | 单一 Python 运行时，便于自包含打包、Windows 复用和本地 ASR 集成 |
| D-03 | 不采用 Electron 作为主框架 | 避免额外引入 Node 运行时和双应用框架；Qt 已能完成播放器、转写文本和波形交互 |
| D-04 | 自包含 onedir 打包 | `.app` 内携带私有 Python、依赖、FFmpeg 和模型；不使用单文件自解压，避免临时目录写入和启动开销 |
| D-05 | 界面进程与 ASR 进程分离 | UI 不直接导入 PyTorch/FunASR；通过独立 worker 进程隔崩溃、隔离内存和便于进度控制 |
| D-06 | 本地进程 IPC，不开放 HTTP 端口 | UI 通过 `QProcess` + JSON Lines 与 worker 通信，避免端口冲突和本机服务安全面 |
| D-07 | 开发期默认 `AppFile`，正式版可选数据目录 | 实验阶段固定使用 `AppFile`；稳定自用版首次启动时选择数据根，并记忆该位置 |
| D-08 | 原始转写不可变 | 纠错和编辑生成新版本，不覆盖 `transcript.raw.json` |
| D-09 | 声纹采用逐成员人工确认建档 | 历次会议中由用户逐成员确认说话人，再从确认片段提取嵌入；不提供批量建档 |
| D-10 | LLM 默认使用 conservative 纠错 | 优先修正 ASR 错字和术语，禁止主动总结或编造事实；会议整理由独立操作触发 |
| D-11 | 报告不绑定固定模板 | 使用可编辑提示词生成 Markdown，保存生成版本，不把章节写死在代码中 |
| D-12 | 所有用户可调参数由 schema 驱动 | 枚举项下拉，数值项数字框/滑杆，高级参数使用校验后的 JSON 覆盖 |
| D-13 | 当前名称使用临时代号 | 产品显示名统一使用 `asrGUI`，直至确定更好的正式名称；Bundle Identifier 为 `com.jerryliiiiii.asrgui` |
| D-14 | 当前仅个人自用 | 使用 Personal Team，不考虑公开发布和分发；当前不引入 Developer ID、notarization 或商店流程 |
| D-15 | 报告时间引用为句子级 | 报告默认包含可点击、可复制的句子级时间引用；不要求词级引用 |
| D-16 | 正式版允许选择数据目录 | 稳定自用版首次启动提供目录选择，之后可从设置切换；开发环境仍默认 `AppFile` |
| D-17 | 声纹逐成员手工确认 | 旧会议片段只有在用户明确关联成员后才可加入该成员档案 |
| D-18 | Windows 仅规划 x64 | 暂不考虑 Windows ARM64，不作为首版或后续近期里程碑 |

## 5. 用户流程

### 5.1 首次启动

1. 应用启动后检查工作区、模型、私有运行时和磁盘空间。
2. 实验构建默认工作区为 `<project-root>/AppFile`。
3. 稳定自用版首次启动时要求用户选择数据根；应用验证读写权限、可用空间和目录隔离后完成初始化，并记住该位置。
4. 用户可设置默认识别配置文件和 LLM 配置；LLM 可选，不配置不影响本地转写。
5. 应用展示数据处理说明：音频与声纹只在本机处理；仅在用户主动执行纠错或生成报告时，将文本发送给已配置的在线 LLM。
6. 应用不自动下载 ASR 模型；构建包中的模型应已随包提供。若模型缺失，显示明确的诊断信息，不静默回退到网络下载。

### 5.2 导入与转写

1. 用户拖入或选择本地音频。
2. 应用读取标题、时长、格式和采样率，并计算源文件 SHA-256。
3. 用户选择：
   - 转写预设：快速、均衡、精细或自定义；
   - 是否复制源音频到会议目录；
   - 是否尝试使用已有声纹匹配固定成员；
   - 高级 ASR 参数。
4. 应用把音频解码为稳定的分析格式，创建会议目录和任务记录。
5. worker 依次执行 VAD、ASR、标点、说话人聚类和声纹匹配。
6. 每个阶段保存检查点；应用展示阶段、进度和预计剩余信息。
7. 完成后进入会议工作台。

### 5.3 查看与定位

1. 转写按说话人和时间段展示。
2. 每个说话人有独立颜色和显示名。
3. 中文以单字为可点击单位，英文以单词为可点击单位，数字和连续符号按规则成组。
4. 点击可点击单位时，播放器跳转到该单位开始时间并默认开始播放。
5. 播放时高亮当前文本单位，并自动滚动到可视区域；用户手动滚动后暂停自动跟随，直到点击“跟随播放”。
6. 点击句子时间戳可定位到句首；双击说话人标题可筛选该说话人。

### 5.4 说话人确认与声纹建档

1. 转写完成后，自动聚类只生成“说话人 1、说话人 2”等临时标签。
2. 用户逐成员播放各聚类片段，确认其真实身份，并改名或关联已有成员。
3. 用户选择“建立声纹档案”时，应用从该说话人的多个清晰片段提取嵌入向量。
4. 每个成员可保存多个嵌入向量，用于适应不同会议室和设备。
5. 下一次会议中，应用先做会议内聚类，再把聚类与成员档案匹配。
6. 低置信度、多人声音相似或重叠说话时，保留为未知说话人，并提示人工确认。
7. 只有用户明确确认的片段才能加入声纹档案；系统不自动用所有识别结果污染成员档案。

没有人工身份确认的旧音频不能直接用于建立“张三”的声纹。第一阶段不提供旧会议批量建档，最终身份关联必须由用户逐个成员确认。

### 5.5 纠错

1. 用户在会议工作台中选择“AI 纠错”。
2. 应用按段发送文本、说话人标签、必要上下文和用户维护的术语表，不发送音频和声纹。
3. LLM 必须按段返回 JSON，禁止改变段落 ID、说话人或凭空增加内容。
4. 应用执行 schema 校验、段落完整性校验、长度异常校验和差异展示。
5. 用户可逐段接受、拒绝或手工修改。
6. 每次保存形成新版本；原始 ASR 永远保留。

### 5.6 报告

1. 用户选择已确认的纠错稿或原始稿。
2. 报告默认附带对应源句的句子级时间引用；用户可关闭引用，但不要求词级引用。
3. 用户在应用内预览 Markdown。点击时间引用可定位到相应句首并播放，时间文本可单独复制。
4. 用户可编辑报告提示词并重新生成。
5. 每次生成保存独立版本，并记录模型、提示词、输入转写版本和时间。

### 5.7 导出

第一阶段至少支持：

- 原始结构化 JSON；
- 纠错结构化 JSON；
- Markdown 报告；
- 纯文本转写。

后续可扩展 SRT、VTT、DOCX 和 PDF。导出动作不删除工作区中的规范数据。

## 6. 功能需求

### 6.1 会议库

- FR-LIB-01：展示会议标题、日期、时长、状态、说话人数量和更新时间。
- FR-LIB-02：支持按标题搜索、按状态筛选和按时间排序。
- FR-LIB-03：支持重新打开、复制文件路径、删除到应用内回收区。
- FR-LIB-04：处理中的会议不能因关闭窗口而丢失状态；下次启动可恢复任务记录。
- FR-LIB-05：删除会议前必须二次确认；只移动应用管理的文件，不删除外部原文件。

### 6.2 音频导入

- FR-AUD-01：支持至少 WAV、MP3、M4A、AAC、FLAC。
- FR-AUD-02：使用随包 FFmpeg/ffprobe 读取格式、时长、声道和采样率。
- FR-AUD-03：转换出 ASR 所需的 16 kHz 单声道 PCM WAV。
- FR-AUD-04：对损坏、无声、超长或权限不足的文件给出可操作错误。
- FR-AUD-05：默认复制源音频到会议目录；可通过设置改为引用原文件，但界面需提示移动原文件会导致无法播放。
- FR-AUD-06：保存源文件哈希、大小、原始文件名、导入时间和复制策略。

### 6.3 FunASR 转写

- FR-ASR-01：本地离线运行，不依赖 ASR 云服务。
- FR-ASR-02：支持 VAD、ASR、标点和说话人处理模型的可配置组合。
- FR-ASR-03：默认普通话配置为 Paraformer 系列 ASR、FSMN-VAD、CT-Punc 和 CAM++ 说话人模型；具体模型版本在 M0 技术验证后锁定。
- FR-ASR-04：输出句子级时间戳和字/词级时间戳。
- FR-ASR-05：JSON 必须记录模型标识、模型版本或哈希、有效参数和软件版本。
- FR-ASR-06：支持取消任务，并在安全阶段边界停止。
- FR-ASR-07：支持从最近检查点继续，避免整段重跑。
- FR-ASR-08：长音频按 VAD 片段和批次处理，避免一次性把全部音频载入内存。

### 6.4 时间戳与音频同步

- FR-SYNC-01：字/词时间单位统一使用整数毫秒。
- FR-SYNC-02：时间区间采用左闭右开 `[start_ms, end_ms)`。
- FR-SYNC-03：中文按字、英文按词、数字按连续组构造可点击 token。
- FR-SYNC-04：标点通常不可点击，但保留其所属句子。
- FR-SYNC-05：点击 token 后播放器定位到 `start_ms` 并播放。
- FR-SYNC-06：播放头每 100 ms 更新一次，高亮覆盖当前时间的最佳 token。
- FR-SYNC-07：播放器支持播放/暂停、前后跳转、倍速和全局时间显示。
- FR-SYNC-08：如果模型只返回字级时间，英文单词可使用其组成字符的最小开始时间和最大结束时间。
- FR-SYNC-09：时间精度必须在 JSON 中标记为 `token`、`interpolated` 或 `segment`。

### 6.5 说话人与声纹

- FR-SPK-01：自动判断说话人数量的合理范围，默认不强制固定人数。
- FR-SPK-02：输出会议内说话人 ID、句子段落和说话人时间轴。
- FR-SPK-03：允许把临时说话人重命名或关联到已有成员。
- FR-SPK-04：允许从人工确认片段建立成员声纹，至少需要累计足够的有效语音。
- FR-SPK-05：支持每名成员保存多个嵌入向量和来源会议记录。
- FR-SPK-06：新会议中按余弦相似度和校准阈值匹配成员。
- FR-SPK-07：匹配置信度不足时显示未知，不强行给出姓名。
- FR-SPK-08：声纹库可导出、备份和删除；删除成员不删除历史会议文本。
- FR-SPK-09：声纹数据不上传给 LLM，不进入报告请求。

### 6.6 参数配置

- FR-PARAM-01：参数 UI 由机器可读 schema 生成，而不是在每个控件中硬编码。
- FR-PARAM-02：枚举项使用下拉框。
- FR-PARAM-03：数值项使用数字框或滑杆，并显示单位和推荐范围。
- FR-PARAM-04：布尔项使用开关。
- FR-PARAM-05：长文本或列表使用文本框或标签编辑器。
- FR-PARAM-06：高级模式允许附加 JSON 参数，但必须校验、保存并显示“未识别参数”警告。
- FR-PARAM-07：预设不隐藏底层值，用户可展开查看当前有效配置。
- FR-PARAM-08：每次转写保存有效参数快照，保证同一条结果可复现。
- FR-PARAM-09：参数 schema 与 FunASR 适配器版本绑定，升级模型后运行兼容性检查。

### 6.7 LLM 纠错

- FR-CORR-01：支持任意 OpenAI-compatible `base_url`、API key 和模型名。
- FR-CORR-02：内置 DeepSeek 配置预设，但允许覆盖。
- FR-CORR-03：只发送文本和必要的上下文，不上传音频、声纹或本地绝对路径。
- FR-CORR-04：按会议分段处理，支持长文本分块和上下文衔接。
- FR-CORR-05：要求返回 JSON，并校验段落 ID 完整性。
- FR-CORR-06：提供原文、纠错稿和差异视图。
- FR-CORR-07：支持人工逐段编辑、接受、拒绝和版本回退。
- FR-CORR-08：纠错后 token 与原始时间戳通过单调对齐生成近似映射；无法可靠映射时降级到句级时间。
- FR-CORR-09：记录 LLM 服务、模型名、请求时间、提示词版本和错误信息。
- FR-CORR-10：提供术语表和固定成员名，用于保持专有名词一致。

### 6.8 报告

- FR-RPT-01：输出 Markdown。
- FR-RPT-02：提示词可编辑、可保存为提示词档案。
- FR-RPT-03：不在代码中强制固定报告章节，首次安装可提供一个可删除的通用提示词。
- FR-RPT-04：默认基于用户确认的纠错稿；用户可明确选择原始稿。
- FR-RPT-05：报告保存版本和生成元数据。
- FR-RPT-06：报告不自动发送到外部服务，只在用户点击生成时调用。
- FR-RPT-07：报告默认包含句子级时间引用；时间文本在应用内可点击定位到句首并开始播放。
- FR-RPT-08：用户可通过上下文菜单复制时间文本；复制内容不依赖应用运行，粘贴后为可读时间。
- FR-RPT-09：报告不要求词级时间引用；同一句中的多个事实共享该句的定位点。

### 6.9 设置与诊断

- FR-SET-01：查看工作区路径、磁盘占用、模型版本和私有运行时版本。
- FR-SET-02：配置 LLM 预设、API key、超时和重试次数。
- FR-SET-03：配置是否在转写完成后自动尝试声纹匹配。
- FR-SET-04：配置日志级别，但日志不得写入完整转写正文或 API key。
- FR-SET-05：提供“导出诊断包”功能，默认只包含环境、版本、错误栈和脱敏配置。
- FR-SET-06：显示并打开当前数据根。
- FR-SET-07：稳定自用版支持更改数据根；切换前完成或停止正在运行的任务，并校验目标目录。
- FR-SET-08：更改数据根时提供迁移确认；迁移完成后更新位置指针，不静默删除旧数据。

### 6.10 打包与部署

- FR-PKG-01：macOS 发行物为 `asrGUI.app`。
- FR-PKG-02：应用内含私有 Python、PySide6、FunASR、PyTorch、FFmpeg 和模型。

## 7. 非功能需求

### 7.1 可移植性

- 核心业务代码只使用 Python 标准库和跨平台依赖。
- 路径处理统一使用 `pathlib.Path`。
- 不依赖 POSIX shell 命令拼接；外部进程通过参数列表启动。
- 不依赖 macOS 专有 API 才能完成核心流程。
- 文件锁、原子替换、进程取消和临时目录均提供 macOS/Windows x64 兼容实现。
- Windows ARM64 不在当前支持范围。

### 7.2 可复现性

- Python 版本固定为 3.11。
- ASR、PyTorch、ModelScope、Qt 等关键依赖精确锁定。
- 模型使用清单记录 ID、来源、版本/修订和哈希。
- 每次转写记录有效参数快照。
- 原始音频、原始 JSON、纠错版本和报告版本均可独立追溯。

### 7.3 隐私

- ASR、声纹提取和匹配全部本地执行。
- LLM 是唯一默认允许联网的功能，且必须由用户显式触发。
- API key 不写入日志、不进入诊断包、不在界面明文常驻。
- 声纹嵌入不上传、不进入报告请求。
- 不收集遥测和使用统计。

### 7.4 稳定性

- ASR 在独立进程中执行，worker 崩溃不应带走 UI 和已完成结果。
- 中间结果原子写入，异常退出后不留下半写 JSON。
- 长音频处理分阶段保存检查点。
- 所有用户可见错误均包含阶段、原因和建议动作。

### 7.5 性能目标

以下为目标而非已实测承诺，M0 之后根据样音修正：

- 启动时只加载 UI 和会议索引，模型按需加载。
- 处理期间 UI 保持可交互和可取消。
- 2 小时会议音频不因一次性载入全部 PCM 而耗尽内存。
- 在 18 GB 统一内存机器上，普通转写峰值内存目标低于 10 GB。
- 音频波形使用多级峰值缓存，避免每次重绘扫描整段音频。
- 转写播放定位误差目标控制在约 300 ms 内；最终以模型时间戳能力和样音测试为准。

### 7.6 可维护性

- FunASR 通过适配器隔离，避免模型 API 变化扩散到 UI。
- LLM 通过 OpenAI-compatible 客户端隔离，不绑定单一供应商 SDK。
- 数据格式带版本号，并提供迁移程序。
- UI 参数由 schema 驱动，新增常用参数不需要重写页面。

## 8. 总体技术架构

### 8.1 技术选型

桌面端采用 **Python 3.11 + PySide6 Widgets**。

选择理由：

1. 只需要一个 Python 运行时，与 FunASR、PyTorch 和音频处理共用依赖树。
2. PySide6 支持 macOS 和 Windows，原生控件、播放器、文件对话框和波形绘制都能覆盖第一阶段需求。
3. 不依赖浏览器或本地 HTTP 服务，减少端口、防火墙和进程生命周期问题。
4. PyInstaller 的 onedir 模式可以把私有 Python、Qt 插件和模型一并打包。
5. 自包含目标下，Qt Widgets 比再引入 Electron/Node 更易控制依赖和目录边界。

音频播放使用 Qt Multimedia；转写文本使用自绘或 `QTextBrowser` 的 token 渲染方案；波形使用自定义 `QWidget`，不引入 Web 技术栈。

### 8.2 进程结构

```text
┌────────────────────────────────────────────────────┐
│ asrGUI / UI 主进程                                  │
│ PySide6 Window                                      │
│ Meeting Library | Transcript | Player | Report      │
│ Task Coordinator | Repository | Settings            │
└───────────────┬────────────────────────────────────┘
                │ QProcess
                │ stdin/stdout JSON Lines
                │ stderr 日志
┌───────────────▼────────────────────────────────────┐
│ asr-worker / 后台进程                               │
│ Job dispatcher                                      │
│ Audio importer | FunASR pipeline | Speaker engine   │
│ LLM client | Report client | JSON schema validation │
└───────────────┬────────────────────────────────────┘
                │ 原子写入
┌───────────────▼────────────────────────────────────┐
│ 数据根（开发默认 AppFile）                          │
│ data / config / cache / logs / tmp                  │
└────────────────────────────────────────────────────┘
```

约束：

- UI 主进程不得导入 `torch`、`funasr` 或 `modelscope`。
- worker 一次只执行一个重任务，MVP 采用串行队列，避免模型和内存竞争。
- worker 退出后，UI 读取已提交的检查点并显示可恢复状态。
- 同一工作区只允许一个应用实例持有写锁。
- worker 日志和协议输出分离：stdout 只放结构化协议，stderr 放日志。

### 8.3 逻辑模块

| 模块 | 责任 |
| --- | --- |
| `WorkspaceManager` | 解析数据根、创建目录、检查写权限和磁盘空间 |
| `MeetingRepository` | 管理会议元数据、索引、状态和版本 |
| `AudioImporter` | 探测、复制、哈希、解码和波形峰值生成 |
| `FunASRAdapter` | 组合 VAD/ASR/标点模型，屏蔽 FunASR 版本差异 |
| `SpeakerEngine` | 聚类、嵌入提取、档案匹配和人工确认接口 |
| `TranscriptService` | token 化、时间戳归一化、JSON 生成和校验 |
| `AlignmentService` | 纠错文本与原始 token 的单调对齐 |
| `LlmClient` | OpenAI-compatible 请求、重试、限流和脱敏 |
| `ReportService` | 提示词组装、Markdown 生成和版本保存 |
| `WorkerClient` | `QProcess` 生命周期、JSON Lines 协议和取消 |
| `TaskCoordinator` | 任务状态机、恢复、进度和错误呈现 |
| `SettingsService` | 参数 schema、用户配置和有效配置快照 |
| `SecretStore` | 本地凭据读写和权限检查 |
| `ModelRegistry` | 模型清单、校验、路径解析和兼容性检查 |

### 8.4 工作进程协议

请求示例：

```json
{"id":"job-001","type":"transcribe","payload":{"meeting_id":"m-001","audio_path":"audio/asr_16k.wav","settings_profile":"balanced"}}
```

事件示例：

```json
{"id":"job-001","event":"progress","stage":"vad","percent":18,"message":"正在检测语音片段"}
```

成功结果示例：

```json
{"id":"job-001","event":"completed","artifact":"transcript/raw.json"}
```

失败结果示例：

```json
{"id":"job-001","event":"failed","stage":"asr","code":"MODEL_LOAD_FAILED","message":"无法加载 ASR 模型","detail_log":"logs/job-001.log"}
```

取消由独立控制消息或进程终止实现；正常取消应等待当前安全阶段完成，避免破坏已写入 JSON。

- 工作区与存储。

## 10. FunASR 处理管线

### 10.1 默认模型配置

默认普通话配置在 M0 验证后锁定，初始候选为：

| 环节 | 初始候选 | 作用 |
| --- | --- | --- |
| VAD | FSMN-VAD | 检测有效语音并切分长音频 |
| ASR | Paraformer 中文模型 | 普通话识别和字/词时间戳 |
| 标点 | CT-Punc | 恢复句读，辅助段落展示 |
| 说话人嵌入/聚类 | CAM++ | 提取说话人嵌入并进行会议内聚类 |

候选不代表最终效果已经验证。M0（执行计划见 [ROADMAP_v0.1.md](ROADMAP_v0.1.md)）必须确认：

1. 模型在 macOS Apple Silicon 和 Python 3.11 下可稳定加载。
2. 模型确实返回可用的字/词时间戳。
3. CAM++ 接口可以获取段落嵌入，并支持会议内聚类和跨会议匹配。
4. 模型许可证允许随桌面应用打包并在本机使用。

若 CAM++ 的官方高层接口不足以完成声纹匹配，允许在 `SpeakerEngine` 内使用同一嵌入模型或经过验证的本地实现，但不得改变上层数据协议。

### 10.2 音频预处理

1. 用 ffprobe 获取容器、编码、时长、声道和采样率。
2. 计算源文件哈希。
3. 若用户选择复制，把原文件放进会议目录。
4. 使用 FFmpeg 生成 ASR WAV：
   - 16 kHz；
   - 单声道；
   - PCM signed 16-bit；
   - 去除元数据和无关轨道。
5. 生成播放降级 WAV，或复用同一份 WAV。若原格式播放不稳定，则自动使用 WAV。
6. 计算多级波形峰值并缓存。

不默认做降噪、回声消除或响度压缩，因为它们可能改变模型训练分布。需要这些处理时作为显式参数和单独实验。

### 10.3 处理阶段

```text
导入校验
  → 音频解码与波形
  → VAD
  → ASR
  → 标点与句子化
  → 说话人嵌入
  → 会议内聚类
  → 已有声纹匹配
  → token 化与时间戳归一化
  → JSON schema 校验
  → 原子提交
```

VAD 片段进入 ASR 时保留稳定片段 ID。标点模型可以改变显示文本，但时间信息以 ASR token 原始时间为主。

### 10.4 长音频

- 按 VAD 片段和配置的批次长度处理。
- 每批完成后追加中间结果并记录进度。
- UI 只读取已提交批次用于预览，最终完成后生成规范 JSON。
- 对超过建议时长的音频给出提示，但不简单拒绝；具体上限由 M0 性能测试决定。
- 取消任务时保留已完成批次，允许恢复。

### 10.5 说话人处理

1. 从语音片段提取说话人嵌入。
2. 过长片段在静音点或稳定窗口处切分。
3. 在会议内做无监督聚类，生成临时说话人。
4. 对每个聚类汇总多个嵌入，并与成员档案进行余弦相似度比较。
5. 达到阈值且与其他候选有足够间隔时，赋成员显示名；否则保留临时 ID。
6. 说话人边界映射回句子和 token。
7. 多说话人重叠区域标记为低置信度，允许人工拆分或重新标注。

说话人匹配的阈值不能由代码硬编码为“永久正确值”。应用提供初始值，并通过历次会议片段校准。每次匹配保存相似度和候选列表，便于解释。

### 10.6 时间戳归一化

- 所有时间转换为整数毫秒。
- 修正负时间、结束早于开始、跨段重叠等异常。
- 中文按字，英文按单词，数字、英文缩写和连续符号按规则成组。
- 标点绑定到前一个 token 的文本显示，但不扩大点击范围。
- 无法得到真实 token 时间时：
1. 在句子范围内按字符长度插值；
2. 标记 `time_precision="interpolated"`；
3. 如果段落都不可信，则使用句级时间并标记 `segment`。

UI 必须尊重精度标记，不把插值时间伪装成精确时间。

### 10.7 参数 schema

初始 schema 至少覆盖以下类别：

| 类别 | 参数示例 | 控件 |
| --- | --- | --- |
| 转写预设 | 快速、均衡、精细、自定义 | 下拉 |
| ASR 模型 | 已登记的普通话模型 | 下拉 |
| VAD 模型 | 已登记的 VAD 模型 | 下拉 |
| 标点模型 | 关闭或已登记模型 | 下拉 |
| 说话人模型 | 关闭或已登记模型 | 下拉 |
| 设备 | CPU、自动、经测试的加速后端 | 下拉 |
| 时间粒度 | 字/词、句子 | 下拉 |
| 批大小 | 秒数 | 数字框 |
| beam size | 预置合法值 | 下拉 |
| VAD 最大单段 | 毫秒或秒 | 数字框 |
| 语音噪声阈值 | 小数 | 滑杆 + 数字框 |
| 标点批大小 | 数值 | 数字框 |
| 说话人数量 | 自动、最小/最大 | 开关 + 数字框 |
| 聚类阈值 | 小数 | 滑杆 + 数字框 |
| 档案匹配阈值 | 小数 | 滑杆 + 数字框 |
| 热词 | 每行一个 | 多行文本 |
| 高级参数 | JSON 对象 | 代码文本框 |

具体参数名、合法范围和默认值由 FunASR 适配器提供，不能把某个版本的内部参数直接当作永久产品契约。

## 11. 原始转写 JSON

## 12. LLM 纠错设计

### 12.1 配置

配置项：

- `provider_name`
- `base_url`
- `model`
- `api_key`
- `timeout_seconds`
- `max_retries`
- `temperature`
- `max_output_tokens`
- `correction_prompt_profile`
- `report_prompt_profile`

内置 DeepSeek 预设，但用户可编辑。API key 与普通配置分离保存。

实验阶段为遵守“不写系统目录”：

- 凭据保存在当前数据根的 `config/secrets.local.json`；实验构建中的数据根为 `AppFile`；
- 文件权限设置为仅当前用户可读写；
- 界面默认遮蔽；
- 日志、诊断包和异常栈不得输出 key；
- 允许用环境变量 `ASRGUI_LLM_API_KEY` 临时覆盖，避免写盘。

本地凭据文件不是强安全容器。当前自用阶段不默认使用系统钥匙串；若未来改变使用范围，再评估系统钥匙串适配器。

### 12.2 纠错模式

MVP 提供两种模式：

1. **保守纠错（默认）**：修正明显的同音错字、标点和专有名词；不删口语、不改结构、不总结。
2. **会议整理**：在不改变事实和说话人的前提下清理重复口头语、改善句子连贯性、形成自然段。

报告生成不自动等同于会议整理。用户可以先整理再报告，也可以直接从原始稿生成报告。

### 12.3 请求边界

只发送：

- 会议标题；
- 分段 ID、说话人显示名（可关闭）；
- 需要纠错的文本；
- 相邻段落的最小上下文；
- 术语表和固定成员名单；
- 输出格式约束。

不发送：

- 音频；
- 声纹嵌入；
- API 路径以外的本地绝对路径；
- 与当前任务无关的会议。

### 12.4 响应格式

要求 LLM 只返回 JSON：

```json
{
  "segments": [
    {
      "segment_id": "seg_0001",
      "corrected_text": "我们先确认一下今天的议题。",
      "notes": []
    }
  ]
}
```

校验：

- 所有输入 `segment_id` 必须且只能出现一次。
- 不接受未知 segment ID。
- 修改长度比例异常时标记为高风险，不自动接受。
- `notes` 仅作为提示，不作为会议事实来源。
- 解析失败、截断或不完整时保留原稿并显示重试建议。

### 12.5 长会议分块

- 按 token/字符预算分块，不按固定字符硬切句子。
- 每块携带有限的前后文，但只允许返回本块 segment。
- 合并后执行全局完整性校验。
- 并发请求数默认为 1，降低限流和费用风险；后续可配置。
- 每次请求记录消耗统计（若供应商返回）和失败原因。

### 12.6 纠错文本到原始时间戳的对齐

原始 token 时间是唯一可信时间源。纠错后文本通过单调字符对齐映射：

- 相同字符：沿用原始时间。
- 替换：沿用被替换范围的起止时间。
- 插入：在前一个 token 结束时间与后一个 token 开始时间之间插值。
- 删除：不生成可点击 token，但保留原始对应关系。
- 整段对齐置信度低：使用 segment 开始时间，UI 标记为近似定位。

纠错 JSON 保存：

- 原始 transcript 版本；
- 对齐映射；
- 每个纠错 token 的时间精度；
- 无法映射的文本范围。

### 12.7 报告提示词

报告不固定模板，提示词至少明确：

- 使用输入事实，不得编造；
- 区分事实、决定、待办和未决问题；
- 不确定内容明确标注；
- 输出纯 Markdown；
- 默认加入对应源句的句子级时间引用；
- 使用用户提供的成员名和术语。

应用可以提供通用提示词作为起点，但用户可完全改写、保存和删除。不得在渲染层偷偷套用代码内置章节。

时间引用约定：

- 可见文本使用 `[HH:MM:SS]`，例如 `[00:12:34]`。
- Markdown 链接目标使用应用内部可识别的 `asrgui://meeting/<meeting-id>/segment/<segment-id>`。
- 应用内 Markdown 预览拦截该链接并定位到对应句子；不要求注册系统级 URL scheme。
- 导出后的引用仍保留可读时间；在应用外不保证可点击。
- 不使用词级引用；同一句中的多个事实共享该句定位点。

- 业务数据仍只写入用户选定的数据根。
- 位置指针只包含数据根路径和格式版本，不包含会议内容或凭据。
- 用户更改数据根时，先验证目标目录，再以原子替换更新位置指针。
- 旧数据根不静默删除；迁移失败时继续指向旧位置并给出可操作错误。

### 13.7 写入与恢复

- JSON 写入流程：同目录临时文件 → flush/fsync → 原子替换。
- 状态更新使用短事务。
- 写锁文件放在 `<data-root>/tmp`。

- 日志轮转并限制大小；不记录完整转写内容和 API key。

## 15. 安全与隐私设计

### 15.1 本地数据

- 音频、转写、声纹和报告均为本地文件。
- 文件权限尽量限制为当前用户。
- 删除会议进入应用内回收区，不直接调用系统删除。
- 声纹库与会议库分开管理。

### 15.2 LLM 调用

- 只在用户明确点击纠错或生成报告时联网。
- 请求前显示将发送的字符数和是否包含说话人姓名。
- 不发送音频和声纹。
- 默认关闭供应商侧调试或训练选项；若供应商不能保证，应在设置中明确提示。
- API key 不写日志、不进入导出诊断包。
- 网络错误、限流和服务端错误提供可读信息，不泄露请求头。

### 15.3 Prompt 注入

会议转写文本可能包含“忽略之前指令”等字样。LLM 客户端必须：

- 将转写内容放在明确的数据边界内；
- 系统提示明确要求把输入当作待处理数据；
- 不向 LLM 提供工具调用能力；
- 不接受 LLM 返回的本地路径、命令或自动执行指令；
- 对返回 JSON 做严格 schema 校验。

### 15.4 文件安全

- 导入文件名清洗后存储在会议 ID 目录中。
- 不将用户文件名直接拼接成可执行命令。
- 外部进程使用参数列表，不使用 `shell=True`。
- SQLite 使用参数化查询。
- 导出目录必须位于用户选定工作区内，防止路径穿越。

## 16. 错误处理与状态机

会议任务状态：

```text
created
  → imported
  → queued
  → decoding
  → vad
  → asr
  → punctuation
  → diarization
  → speaker_matching
  → finalizing
  → completed
```

异常状态：

- `cancelled`
- `failed`
- `interrupted`

规则：

- 每个状态变化写入 `meeting.json`。
- 失败保留已完成的阶段产物。
- 用户可以从最后一个有效检查点重试当前阶段。
- 模型缺失、音频损坏、磁盘不足、权限不足和 schema 校验失败使用不同错误码。
- worker 崩溃时 UI 读取 stderr 日志尾部并给出恢复选项。
- 错误消息以用户能执行的动作结尾，例如“释放空间”或“重新选择音频”。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| FunASR 在 macOS ARM64 的接口或模型兼容性不足 | 无法实现离线转写 | M0 优先验证；锁定可用版本；适配器隔离 |
| 字级时间戳实际粒度与英文单词需求不一致 | 点击定位不够精确 | 以字符时间聚合英文单词；标记时间精度；句级回退 |
| 说话人分离对重叠语音效果有限 | 姓名错配 | 自动结果必须可人工修正；低置信度不猜身份 |
| 历次会议片段数量不足 | 声纹匹配不稳定 | 要求累计有效语音；每成员保存多嵌入；未知回退 |
| LLM 改写过度或漏段 | 纠错稿不可信 | JSON 约束、完整性校验、差异视图、默认保守模式 |
| 纠错后 token 无法一一对应 | 时间定位漂移 | 单调对齐、插值、句级降级和 UI 精度提示 |
| 自包含包体积过大 | 磁盘和分发困难 | 精简依赖；模型清单；构建目录统计；清理前征得确认 |
| PyInstaller 漏打包 Qt 插件/动态库 | 另一台机器启动失败 | 干净环境验收；收集日志；打包测试纳入 CI |
| Windows x64 音频后端和路径差异 | Windows x64 构建失败 | 抽象平台层；Windows CI；单独里程碑验收；ARM64 不纳入范围 |
| 模型和 FFmpeg 许可证不明确 | 本机随包及未来对外分发受限 | 打包前逐个核对；保留许可证文件；必要时更换构建 |
| API key 本地保存安全不足 | 凭据泄露 | 默认遮蔽、0600 权限、环境变量覆盖、日志脱敏；扩大使用范围前再评估系统钥匙串 |
| 长会议内存峰值 | 应用崩溃 | VAD 批处理、分阶段落盘、模型懒加载、性能门槛测试 |

## 20. 文档版本与命名策略

### 20.1 命名规则

- 设计与开发计划统一存放在 `Assets/doc`。
- 文件名使用 `<TYPE>_v<MAJOR>.<MINOR>.md`，其中 `TYPE` 使用大写英文名称。
- 当前配套文件为 `DESIGN_v0.1.md` 和 `ROADMAP_v0.1.md`。
- 文件版本号必须与页首“文档版本”完全一致，例如版本 `0.2` 对应 `DESIGN_v0.2.md`。
- 设计与路线图互相引用同一版本的文件，不跨版本引用作为默认基线。
- 当前版本存放在 `Assets/doc`；历史版本存放在 `Assets/doc/history`。

### 20.2 更新规则

- 0.1 是初始基线。
- 0.1 定稿后，任何后续内容更新都新增下一版本文件，不在已有版本上修改。
- 设计与路线图任一方发生内容变化时，同步生成同版本的两份新文件；未变化部分从上一版本复制后保持原意。
- 新版本只引用同版本的配套文档。
- 新版本确认后，将上一版的设计与路线图成对移动至 `Assets/doc/history`，保留原文件名，不覆盖、不修改已归档版本。
- 版本递增示例：在 `Assets/doc` 新增 `DESIGN_v0.2.md` 和 `ROADMAP_v0.2.md`，再将 0.1 版两份文件移动至 `Assets/doc/history`。
- 文档内的相对链接必须能在版本文件所在目录直接解析。
