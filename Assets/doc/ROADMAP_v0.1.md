## 1. 文档目的

本文档定义 asrGUI 的开发阶段、阶段性目标、交付物、验收出口和阶段依赖。产品范围、技术架构、数据格式、交互细节和功能需求以 [DESIGN_v0.1.md](DESIGN_v0.1.md) 为准。

本文档只规划当前个人自用目标，不包含公开发布、商店上架、对外分发或 Windows ARM64 支持。

## 3. 测试音频基线

两份本地测试音频位于 `Assets/audio`。媒体文件由 `.gitignore` 排除，不进入版本库，也不随应用分发。

| 用途 | 文件 | 时长 | 格式 |
| --- | --- | --- | --- |
| 首轮转写、标点、时间戳、点击定位 | `Assets/audio/reference_rec_5min.mp3` | `00:05:20.095` | MP3，48 kHz，双声道，128 kbps |
| 长音频、内存、取消与恢复 | `Assets/audio/reference_rec_30min.m4a` | `00:30:11.541` | M4A，ALAC，48 kHz，双声道 |

使用要求：

1. 测试时由应用把音频复制到对应会议目录。
2. 分析音频统一转换为 16 kHz、单声道、PCM signed 16-bit WAV。
3. 不修改或移动 `Assets/audio` 中的原文件。
4. 30 分钟样本用于验证长音频首个性能门槛；设计中的 2 小时内存目标在 M2 中用受控长输入继续验证。
5. 测试音频和任何派生媒体不得提交到 Git，也不得进入最终应用包。

## 5. M0：环境与模型验证

### 5.1 阶段目标

在正式展开 UI 前，用最小命令行和原型验证 FunASR、时间戳、说话人处理、长音频内存和自包含打包是否可行。M0 的结论决定首版模型与依赖版本。

### 5.2 工作包

1. 在 `Codex_work_space` 使用 Homebrew Python 3.11 创建独立 `.venv`，项目依赖只安装在该虚拟环境。
2. 安装并锁定 FunASR、PyTorch、ModelScope、PySide6、音频处理和打包依赖。
3. 准备可离线加载的首版候选模型，记录来源、修订、许可证和文件哈希。
4. 在断网条件下加载模型并转写 `reference_rec_5min.mp3`。
5. 检查句子、字/词 token 的时间单位、边界、精度和标点影响。
6. 检查 CAM++ 的说话人嵌入、会议内聚类和跨会议相似度接口。
7. 使用 `reference_rec_30min.m4a` 测量模型加载时间、处理耗时、峰值内存、取消和恢复行为。
8. 用最小 PySide6 窗口、独立 ASR worker 和 PyInstaller 原型验证进程通信、Qt 插件与模型资源打包。
9. 使用 Bundle Identifier `com.jerryliiiiii.asrgui` 生成最小 macOS 应用，并验证 Personal Team 本地签名后能够启动。
10. 记录模型、Qt、FFmpeg 和 PyTorch 的许可证与随包使用条件。

### 5.3 交付物

- 可复现的 Python 3.11 虚拟环境和依赖锁文件。
- 可离线运行的最小 ASR 脚本。
- 两份测试音频的处理记录。
- token 时间戳、标点和说话人能力结论。
- 30 分钟音频的耗时与峰值内存记录。
- 最小 PySide6 + worker + PyInstaller 打包原型。
- 首版模型与依赖锁定清单。
- 明确的 go / no-go 结论和遗留风险。

### 5.4 出口条件

同时满足以下条件才进入 M1：

- 在完全断网条件下可以加载模型并完成两份样音转写。
- 能取得可用的句子级时间信息；token 时间可用或有明确降级策略。
- 说话人嵌入和会议内聚类接口可运行，人工确认建档路径技术上可行。
- 30 分钟样音不会因一次性载入全部 PCM 导致失控内存。
- 最小应用能在未依赖系统 Python 和 FFmpeg 的情况下启动 worker 并返回结果。
- 首版模型与依赖版本、许可证和打包边界已记录。

若任一项不满足，先调整模型、依赖或适配方案，不以 UI mock 数据继续推进。

## 6. M1：桌面壳与数据根

### 6.1 阶段目标

建立可持续扩展的 PySide6 桌面基础，让会议库、数据根、导入、状态和日志先形成可靠骨架。

### 6.2 交付物

- PySide6 主窗口和基础导航。
- `WorkspaceManager`：开发构建默认 `AppFile`，稳定构建支持用户选择数据根。
- 数据根位置指针、权限校验、目录初始化和切换前的任务保护。
- 会议库列表、空状态、搜索和状态筛选。
- 音频导入、ffprobe 探测、格式校验、源文件复制和 SHA-256 记录。
- 波形峰值生成与显示。
- 本地配置、滚动日志、回收区和可恢复的会议状态。
- mock worker 的排队、进度、失败和取消流程。

### 6.3 出口条件

- 开发构建启动后只使用 `AppFile` 内的业务数据。
- 稳定构建可以在首次启动选择空目录，重启后继续使用同一数据根。
- 导入两份测试音频时能显示正确时长、格式、声道和采样率。
- 关闭并重新打开应用后，会议列表、任务状态和导入记录仍然一致。
- mock worker 可以在不阻塞 UI 的情况下完成、失败和取消任务。

---

## 7. M2：离线 ASR 与播放同步

### 7.1 阶段目标

把 M0 验证过的模型接入真实 worker，完成从导入音频到可浏览、可定位转写的闭环。

### 7.2 交付物

- FunASR worker 和稳定的 JSON Lines 进程协议。
- VAD、ASR、标点、说话人嵌入和会议内聚类的阶段化管线。
- 正式 `transcript.raw.json`、schema 校验和检查点恢复。
- 参数 schema、常用参数控件和高级 JSON 覆盖。
- 转写视图：说话人、句子和可点击 token。
- 音频播放器、token 跳转、当前文本高亮和手动跟随控制。
- 长音频批处理、取消、失败重试和中间结果预览。

### 7.3 出口条件

- 两份测试音频都能离线完成转写并生成符合 schema 的 raw JSON。
- 点击句子或 token 可以定位到可接受误差范围内的音频位置。
- 30 分钟样音处理期间 UI 保持响应，可以取消并从有效检查点恢复。
- 模型缺失、音频损坏、权限不足和磁盘不足能显示不同且可操作的错误。
- 2 小时内存目标在受控长输入测试中达到设计门槛，或形成经过确认的修订基线。

---

## 8. M3：说话人与声纹

### 8.1 阶段目标

让会议内自动聚类能够经过人工确认转化为可靠的成员档案，并在新会议中提供可解释的匹配结果。

### 8.2 交付物

- 会议内说话人聚类。
- 说话人试听、人工改名和成员关联。
- 逐成员从多个已确认片段提取嵌入并建立声纹档案。
- 每成员多嵌入、有效语音时长和来源会议记录。
- 跨会议匹配、相似度候选、阈值和未知说话人回退。
- 声纹库查看、导出、备份和删除。

### 8.3 出口条件

- 用户可以逐成员确认身份和建立声纹，不提供旧会议批量建档入口。
- 使用第一段会议建立声纹后，第二段会议能显示匹配候选和相似度。
- 低置信度结果不会被静默赋名，界面保留人工确认路径。
- 删除声纹成员不会删除历史会议文本，音频和声纹不进入 LLM 请求。

## 9. M4：LLM 纠错与报告

### 9.1 阶段目标

在不可变原始转写之上增加受控纠错和 Markdown 报告，并形成可用的句子级时间引用。

### 9.2 交付物

- OpenAI-compatible 客户端和可编辑配置。
- DeepSeek 预设，但保持供应商可替换。
- 保守纠错与会议整理两种模式。
- 分段 JSON 协议、完整性校验、重试和失败降级。
- 原文、纠错稿、差异视图和逐段接受/拒绝。
- 纠错 token 到原始时间戳的单调对齐和句级回退。
- 可编辑、保存和删除的提示词档案。
- Markdown 报告生成、预览、手工编辑和多版本保存。
- 默认句子级时间引用：可点击定位句首，可复制可见时间。

### 9.3 出口条件

- 原始转写永不被纠错或报告覆盖。
- LLM 缺段、重复段、非 JSON、截断和超长响应不会破坏已保存版本。
- 音频、声纹和无关本地路径不进入请求；日志和诊断包不包含 API key。
- 报告默认包含句子级引用，应用内点击可定位并播放，复制后得到可读时间。
- 在应用外打开导出报告时，时间文本仍然可读，不依赖应用运行。

## 10. M5：稳定自用版

### 10.1 阶段目标

把已验证能力封装为可在当前 Mac 上稳定重复使用的自包含应用。该阶段是个人自用稳定版，不是公开发布。

### 10.2 交付物

- PyInstaller onedir 形式的 `asrGUI.app`。
- Bundle Identifier `com.jerryliiiiii.asrgui`。
- 随包私有 Python、Qt、FFmpeg、FunASR、PyTorch 和模型。
- Personal Team 本地签名和本机 Gatekeeper 启动说明。
- 首次启动数据根选择、位置记忆和更改目录流程。
- 应用内诊断、版本信息、模型清单和许可证文件。
- 开发、构建、部署和故障排查说明。

### 10.3 出口条件

- 在未安装项目 venv、Homebrew Python 和系统 FFmpeg 的 macOS 用户环境可启动。
- 离线完成导入、转写、说话人确认、纠错、报告和播放定位。
- 首次启动可选择数据根，重启后保持；迁移失败不影响旧数据。
- 业务数据只写入当前数据根，应用包保持只读。
- 满足设计文档中的 AC-01 至 AC-14。
- 不需要 Developer ID、notarization、商店元数据或对外安装器。

## 11. M6：Windows x64 可移植性

### 11.1 阶段目标

在不影响 macOS 主线的前提下，评估同一业务代码在 Windows x64 上构建和运行的能力。该阶段在 M5 完成后按需启动，不作为当前自用版本的阻塞项。

### 11.2 交付物

- Windows x64 目录版构建配置。
- Windows 音频后端、路径、锁、临时目录和进程取消适配。
- `windows-latest` CI 冒烟测试。
- Windows x64 实机导入、转写和播放测试记录。

### 11.3 出口条件

- Windows x64 能启动应用、导入音频、加载随包模型并完成一次离线转写。
- 路径、Unicode 文件名、音频播放和 worker 取消通过冒烟测试。
- 不要求安装器、Authenticode、公开发布或商店流程。
- Windows ARM64 不在本阶段范围内，也不设置验收条件。

## 12. 阶段依赖与质量控制

| 依赖 | 说明 |
| --- | --- |
| M0 → M1 | 模型、时间戳和打包基础未验证时，不开始大规模 UI 开发 |
| M1 → M2 | 数据根、会议状态和 worker 协议稳定后接入真实 ASR |
| M2 → M3 | 句子与 token 时间可用后，才能可靠试听和确认说话人 |
| M3 → M4 | 成员身份和原始转写稳定后，再用 LLM 处理文本 |
| M4 → M5 | 核心闭环通过后，再进行稳定打包与干净环境验收 |
| M5 → M6 | 当前自用闭环稳定后，再投入 Windows x64 适配 |

质量控制规则：

1. 每个阶段完成时更新对应文档或增加实施记录。
2. 所有性能、准确率和兼容性结论必须来自真实样音或实际构建。
3. 数据格式、打包边界、LLM 请求内容、数据根位置或任一份配套文档发生变化时，按设计文档的版本策略同时新增 `DESIGN_v<MAJOR>.<MINOR>.md` 与 `ROADMAP_v<MAJOR>.<MINOR>.md`；新版本确认后，将上一版两份文件成对移动至 `Assets/doc/history`，不修改已归档版本。
4. 构建产物、模型缓存和中间目录可能占用数 GB；项目接近完成后先确认，再清理。
5. 新增 Python 依赖始终安装到项目虚拟环境，不使用全局环境。

6. 根据结果锁定模型与依赖，再决定是否进入 M1。
